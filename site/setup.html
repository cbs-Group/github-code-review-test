One-time setup

A repository admin does these steps once. Afterwards anyone with write access can run the demo.

Prerequisites

  • Copilot code review is enabled for the organization (organization settings → Copilot → Policies).
  • Demo users have a Copilot license, or the organization allows members without a license to use Copilot code review.
  • You are an admin of this repository.

1. Request Copilot automatically with a ruleset

  1. Open Settings → Rules → Rulesets and click New ruleset → New branch ruleset.
  2. Name it, for example copilot-review, and set Enforcement status to Active.
  3. Under Target branches, click Add target → Include default branch.
  4. Under Branch rules, select Automatically request Copilot code review.
  5. Optionally enable Review new pushes (Copilot reviews each push again) and Review draft pull requests.
  6. Click Create.

Without the ruleset the demo still works: open the pull request, then choose Copilot under Reviewers. Each user can also turn on automatic review for their own pull requests in their personal Copilot settings → Code review.

2. Review settings (optional)

Open Settings → Copilot → Code review in the repository:

  • Review effort level for automatic reviews: Lite, Balanced or Max.
  • Use custom instructions is on by default; keep it on so the files in .github/ take effect.
  • Auto-approval: leave off for this demo.

3. GitHub Pages

  1. Open Settings → Pages and set Source to GitHub Actions.
  2. Run Actions → Deploy site → Run workflow once. Later pushes to site/ on main deploy automatically.
  3. The site URL is shown in Settings → Pages and in the workflow run.

If Deploy site fails in configure-pages with Get Pages site failed … Not Found, Pages is not enabled yet: set the source as in step 1 and re-run the workflow.

This repository is private. GitHub Pages for private repositories needs a paid plan, and the site is public unless your organization uses GitHub Enterprise Cloud and you set the Pages visibility to Private. Check what your organization allows before publishing internal content.

4. Branch housekeeping

  • Demo pull requests are closed without merging, so their branches stay until someone clicks Delete branch on the pull request. (Automatically delete head branches only applies to merged pull requests.)
  • The Create demo branch workflow declares permissions: contents: write itself. No change to the default workflow permissions is needed unless an organization policy blocks it.
  • Optionally require the CI check on main in the same ruleset.
