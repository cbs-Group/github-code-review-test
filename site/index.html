GitHub Copilot code review

Copilot reviews a pull request like an extra teammate: it reads the change, leaves inline comments, and proposes fixes you can commit with one click. This repository lets you watch that happen on a small TypeScript project.

Try the review flow →

How the flow works

1Run workflow→ 2Branch pushed→ 3Open pull request→ 4Copilot requested→ 5Review comments→ 6Fix & re-review
  1. Run the workflow. In Actions → Create demo branch you pick a scenario, for example a logic bug or a security problem.
  2. Branch pushed. The workflow copies the scenario files over main and pushes a branch called demo/<scenario>-<run number>.
  3. Open the pull request. The job summary has a link that opens a prefilled pull request. You are the author, just as in real work.
  4. Copilot is requested. A repository ruleset adds Copilot as a reviewer automatically. You can also add it by hand under Reviewers.
  5. Review comments arrive. Copilot leaves inline comments, often with suggested changes. CI runs in parallel.
  6. Fix and re-review. Commit a suggestion or push a fix, ask Copilot to review again, then close the pull request.

What Copilot does in a review

  • Reads the diff plus surrounding project context. The agentic part runs on GitHub Actions runners.
  • Leaves a review with inline comments. Many comments include a suggested change you can commit directly.
  • By default it submits a Comment review, so it does not block merging and does not count as a required approval. Admins can opt in to Copilot approvals.
  • Follows custom instructions from the pull request's head branch, so you can test instruction changes inside the same pull request.
  • Supports review effort levels Lite, Balanced (default) and Max.

Copilot is a reviewer, not the reviewer. It can miss problems and can be wrong. Keep human review for anything that matters.

Who can use it, and who pays

Copilot code review is part of Copilot Pro, Pro+, Max, Business and Enterprise. On Business and Enterprise, organization owners can also let members without a Copilot license use it; that usage is billed to the organization.

A review consumes AI credits for the model and GitHub Actions minutes for the agentic context gathering.

How the review startsAI credits are attributed to
Someone requests Copilot under ReviewersThe person who requested it
Automatic review (ruleset or personal setting)The pull request author
Pull request authored by Copilot cloud agentThe human co-author, otherwise the organization
Pull request authored by another bot (for example github-actions[bot])The organization

That last row is why this demo pushes only a branch and lets you open the pull request: billing follows your license, and CI runs normally. Pull requests created with GITHUB_TOKEN would not trigger other workflows.
