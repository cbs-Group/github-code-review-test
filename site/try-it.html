Try the review flow

About five minutes from start to the first Copilot comment.

Open “Create demo branch” →

Step by step

  1. Start the workflow. On the workflow page click Run workflow, choose a scenario (see below), and click Run workflow again.
  2. Open the run. When it finishes, open it. The Summary shows the branch name, a link, and what Copilot should find.
  3. Create the pull request. Click Open the pull request. Title and description are prefilled; keep main as base and click Create pull request.
  4. Wait for Copilot. With the ruleset active, Copilot appears under Reviewers and starts on its own. Without it, click Reviewers and select Copilot. A review usually takes a few minutes.
  5. Read the review. Open Files changed or the Conversation tab. Compare the comments with the expected findings from the job summary.
  6. Act on a comment. Use Commit suggestion on a suggested change, or reply and resolve the conversation. Rate comments with 👍 / 👎 to give feedback.
  7. Re-review. If Review new pushes is on, Copilot reviews the new commit automatically. Otherwise click the re-request button next to Copilot under Reviewers.
  8. Clean up. Close the pull request without merging and click Delete branch.

Scenarios

ScenarioWhat the change doesWhat Copilot should flag
logic-bug“Simplifies” tax math and applies a loyalty discount to the totalDiscount applied twice; tax returns fractional cents
securityMakes local setup “easier” and adds lookup loggingHardcoded fallback API key; missing email validation; password hash in logs
conventionsAdds a price formatting helperany, console.log and no test – rules from .github/copilot-instructions.md
cleanAdds a tested, locale-aware currency formatterLittle or nothing – a control to show Copilot does not invent issues

All scenarios compile and keep the existing tests green, so CI passes and only the review catches the problems. Copilot is non-deterministic: wording, number and order of comments vary between runs.

Experiment with instructions

Copilot reads custom instructions from the pull request's head branch. In a demo pull request, edit .github/copilot-instructions.md – for example, remove the severity tag rule or add “Flag every function longer than 10 lines” – push, and request a new review. Compare the comments.

Create a demo branch locally

npm ci
node scripts/create-demo-branch.mjs list
node scripts/create-demo-branch.mjs apply security
git switch -c demo/security-local
git add -A
git commit -m "demo: apply security scenario"
git push -u origin HEAD

Then open a pull request from that branch as usual.

Troubleshooting

SymptomCheck
Copilot is not offered under ReviewersYou have no access to Copilot code review: missing license, or the organization policy is off.
No automatic review startedRuleset is not Active or does not target main; the pull request is a draft and draft reviews are off. Request Copilot manually.
Review fails or never finishesAI credit budget or quota is exhausted, or GitHub-hosted runners are disabled for the organization. Re-request after fixing.
Workflow fails at git pushAn organization policy restricts GITHUB_TOKEN write access, or a ruleset blocks creating demo/* branches.
